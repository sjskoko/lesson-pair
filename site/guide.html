The installable directory is skills/lesson-pair. Review the source and use your host's supported skill installer. Host availability and workspace policies vary.

Custom GPT without a skill loader

Use the portable prompt below and supply the skill instructions and their linked references as instructions or knowledge. This is manual adaptation, not automatic installation. Access to browsing, knowledge files, actions, and Notion varies by product.

Organize my language lesson into two linked pages: preparation and review.
Use LessonPair's SKILL.md and read its references only as needed.
Preserve my original writing and teacher feedback verbatim.
Label AI corrections. Do not invent a transcript, missing meaning,
score, or completed practice. Reuse the existing session if present.
If you cannot write to Notion, provide drafts and say they are unsaved.

Set up the paired Notion structure

Use one study hub with a Sessions database. Each session contains two child pages: preparation and review. Put links to both pages in the session row and add a reciprocal link inside each page.

Session propertyUse
Name, session number, lesson dateIdentify the lesson; check for a match before creating a new one.
Preparation page, review pageOpen either half directly from the database.
Status, next review dateBuild a review-pending view and a calendar. Mark completion only when confirmed.
Organization dateKeep filing time separate from the actual lesson date.

Useful views: all sessions, review pending, calendar, and reusable templates. Keep template rows out of lesson-only views. Preserve the current schema when adapting an existing hub. The Notion workflow reference explains the write and verification steps.

  1. Prepare from the supplied video and available transcript.
  2. Capture original writing and teacher notes after the conversation.
  3. Add attributed corrections and three reusable expressions.
  4. Answer a short recall exercise, then rewrite without looking.
  5. Choose a review date and confirm completion yourself.

Run the local formatter without an AI model

Requires Git and Python 3.10 or later. No third-party runtime packages, API key, or model tokens are needed. The input is newly written fictional material.

git clone https://github.com/sjskoko/lesson-pair.git
cd lesson-pair
python3 skills/lesson-pair/scripts/lesson_pair.py render examples/lesson.synthetic.json --out output/demo
python3 skills/lesson-pair/scripts/lesson_pair.py check output/demo/02-review.notion.md

Open output/demo/session.md. The output contains preparation and review drafts plus a byte-preserved copy of the source JSON. The renderer formats supplied data; it does not generate corrections, watch videos, or save to Notion. It refuses to overwrite existing output files. Use a new output directory for another run.

See the JSON field reference when preparing your own input. Keep real input and output private.

When something looks wrong

Notion displays literal <table> tags

The .notion.md drafts use Notion MCP enhanced Markdown. Ordinary editor paste may display markup instead of a table. Use the connected tool's supported write format, then fetch the saved page and check its table rows and cells. A successful API response alone does not prove the table rendered correctly.

The assistant cannot find a transcript or save a page

Supply the transcript or accept clearly limited preparation. If the Notion connection is unavailable, request drafts and an explicit unsaved status. A public repository does not grant access to your workspace.

Keep lesson records private

Only synthetic examples belong in public issues, pull requests, demos, or screenshots. Keep learner writing, teacher conversations, private Notion IDs, and credentials outside the public repository. The ignored private/ and local/ folders reduce accidental staging, but they are not an access-control system.

The Python utilities have no network calls or telemetry. If you use an AI assistant and Notion, those services process the data you authorize. LessonPair has no backend. Its MIT license does not waive your model provider's fees or usage limits.

Reference entry points for AI assistants

Start with the small skill entry point, then retrieve only the references needed for the task. These are public files; reading them does not require a personal GitHub access token for ordinary public access, although provider rate limits may apply.

  • Raw SKILL.md — purpose, workflow choices, preservation rules.
  • llms.txt — compact documentation and source link index.
  • llms-full.txt — plain-text introduction, setup, and current skill references.
  • project.json — project identity and stable entry points.

The text index is a convenience for direct retrieval. It does not install a skill into every GPT, eliminate model tokens, or guarantee search indexing or AI citations.
